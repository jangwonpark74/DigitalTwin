# SKT base station data fetch method

This document records how the Gangnam drive-test example obtained nine SKT 5G base-station locations from the public KCA 전파누리 radio-station map. The station coordinates are copied from official registered records. The example drive-test KPIs, serving-cell assignments, antenna heights and sector configurations are synthetic.

The method supports a street-map demonstration around Nonhyeon-dong, Teheran-ro and Gangnam. It does not establish current operating status, surveyed antenna positions, complete SKT coverage or measured network performance.

## Source and collection time

The source was the Korea Communications Agency's [이동통신 무선국 찾기](https://spectrummap.kr/gis/mobile_service.do?menuNo=300480) service. Collection completed at **2026-10-01 15:59:20 UTC**, or **2026-10-02 00:59:20 KST**. This is a retrieval time; the underlying records' publication and last-update dates were not supplied in the selected map responses.

The public map supplied station names, installation addresses, operator names, raw permit UIDs, registered service classifications and geographic positions. No SKT internal system, login, private API, API key, crowd-estimated tower location or address geocoding was used.

The retained source records and exact coordinates are in [sources.json](../examples/gangnam-drive-test/sources.json). They allow the selected locations to be checked even if the public service changes later.

## Endpoint discovery

1. Open the official map page or fetch its HTML using an ordinary browser User-Agent and HTTP/1.1.
2. Read the public JavaScript bundle referenced by that HTML. The bundle used during this collection was `/static/js/main.d7be55b8.chunk.js`; its name can change, so discover it from the page when repeating the process.
3. Follow the map's public request flow. Its URL helper changes `mobile_service.do` to `mobile_service.json`. The request contains map latitude, longitude, zoom and visible radius.
4. Read the returned `points` array. It contains relative `/geojson.do?geojson=...` URLs generated by the service. Fetch those URLs as returned. Their query values are opaque service payloads; they are not API keys and were not decoded or modified.

The discovery request actually used was:

```bash
curl -L --fail --http1.1 --max-time 30 -A 'Mozilla/5.0' \
  'https://spectrummap.kr/gis/mobile_service.json?menuNo=300480&type=&latitude=37.5038&longitude=127.035&zoom=16&visibleRadius=1000' \
  --output discovery.json
```

| Parameter | Value used | Meaning in the map request |
| --- | --- | --- |
| `menuNo` | `300480` | Mobile radio-station locator |
| `type` | Empty | Map data discovery request |
| `latitude` | `37.5038` | Map center latitude |
| `longitude` | `127.035` | Map center longitude |
| `zoom` | `16` | Map zoom |
| `visibleRadius` | `1000` | Requested visible radius in meters |

The response returned four point-list URLs. Their responses contained **15,275 unique mixed-operator station records** in this collection. They covered a wider area than a 1 km circle. The frontend applies operator, service and distance filtering to these lists, so `visibleRadius=1000` must not be treated as a guaranteed server-side geographical limit.

This is an observed public web application's endpoint flow, not a versioned API contract. A repeat fetch should discover the current response URLs and validate the schema before using the records.

## SKT and station selection

The public map's SKT selector contained these customer codes:

```text
542604, 2390, 48805, 541309, 521297, 195403
```

All nine records selected for this example used `customer_no=542604` and `customer_name="에스케이텔레콤 주식회사"`. Selection required the following fields:

| Field | Required value | Interpretation |
| --- | --- | --- |
| `customer_no` | One of the map's SKT customer codes | Operator classification |
| `customer_name` | `에스케이텔레콤 주식회사` in the selected records | Explicit operator name check |
| `cls_name` | `기지국` | Base station, excluding repeater records |
| `is_allow` | `Y` | The map record's permission flag; not evidence of live operation |
| `service_code` | `43` | The selected records identify 5G NR at 3.5 GHz |
| `service_name` | Contains `지상`, excludes `옥내` and `지하` | Outdoor above-ground installation classification |
| `position` | Two finite decimal coordinates | Longitude followed by latitude |

Records were deduplicated by raw `uid`. Different permit records at the same coordinates were not automatically merged. Nine records were then chosen along the requested street loop. This is a small demonstration inventory, not every SKT station in Gangnam.

## Reproduce the station fetch

Run this standard-library Python example in a separate output directory. It discovers fresh point-list URLs, downloads the public records, verifies the exact selected permit records and saves the selected source JSON. It stops if a selected record is missing or no longer matches the expected operator or installation classification.

```python
import json
import math
from datetime import datetime, timezone
from pathlib import Path
from urllib.parse import urljoin
from urllib.request import Request, urlopen

origin = "https://spectrummap.kr"
query = (
    origin + "/gis/mobile_service.json?menuNo=300480&type="
    "&latitude=37.5038&longitude=127.035&zoom=16&visibleRadius=1000"
)
skt_codes = {542604, 2390, 48805, 541309, 521297, 195403}
selected_uids = [
    "322018110056585", "322018110055586", "322018110056120",
    "322019110082019", "322018110056128", "322020110028086",
    "322023110030420", "322022110051374", "322022110014953",
]

def get_json(url):
    request = Request(url, headers={"User-Agent": "Mozilla/5.0"})
    with urlopen(request, timeout=30) as response:
        return json.load(response)

discovery = get_json(query)
point_urls = discovery.get("points")
if not isinstance(point_urls, list) or not point_urls:
    raise RuntimeError("The public map did not return station data URLs")

records = {}
for relative_url in point_urls:
    url = urljoin(origin, relative_url)
    if not url.startswith(origin + "/geojson.do?"):
        raise RuntimeError("Unexpected point-list URL; inspect the public map")
    payload = get_json(url)
    if not isinstance(payload, list):
        raise RuntimeError("Station response schema changed")
    for record in payload:
        uid = str(record["uid"])
        if uid in records and records[uid] != record:
            raise RuntimeError("Conflicting station records for " + uid)
        records[uid] = record

selected = []
for uid in selected_uids:
    record = records[uid]  # A missing permit stops the collection.
    service = record["service_name"]
    valid = (
        int(record["customer_no"]) in skt_codes
        and record["customer_name"] == "에스케이텔레콤 주식회사"
        and record["cls_name"] == "기지국"
        and record["is_allow"] == "Y"
        and str(record["service_code"]) == "43"
        and "지상" in service
        and "옥내" not in service
        and "지하" not in service
    )
    if not valid:
        raise RuntimeError("Selected station classification changed: " + uid)
    longitude, latitude = record["position"]
    if not all(math.isfinite(v) for v in (longitude, latitude)):
        raise RuntimeError("Non-finite coordinates: " + uid)
    if not (127.0 < longitude < 127.1 and 37.48 < latitude < 37.54):
        raise RuntimeError("Unexpected Gangnam coordinates or axis order: " + uid)
    selected.append(record)

snapshot = {
    "retrievedAt": datetime.now(timezone.utc).isoformat(),
    "queryUrl": query,
    "coordinateSystem": "EPSG:4326",
    "records": selected,
}
with Path("skt-selected-source.json").open("x", encoding="utf-8") as output:
    json.dump(snapshot, output, ensure_ascii=False, indent=2)
    output.write("\n")
print(f"Saved {len(selected)} selected SKT registered station records")
```

Repeat collections can return changed coordinates or missing permits. Retain each new snapshot and compare it with the original before regenerating the example. Do not silently substitute a geocoded address or a community-estimated cell location when a registered record disappears.

## Coordinate handling in the application

The returned `position` is `[longitude, latitude]`. The example copies it into WGS84 decimal-degree project coordinates:

```json
{
  "radioLocation": {
    "latitude": 37.511022,
    "longitude": 127.021867,
    "source": "manual"
  }
}
```

`manual` is the application's existing enum for supplied coordinates. It does not mean the positions were guessed. Each site's additional `locationProvenance` contains the KCA source URL, raw permit UID, station name, operator, address and retrieval time. The application's schematic `x` and `y` values are derived from these coordinates with `geoToMapPercent`; they do not replace the geographic positions used by the 3D map.

The map record did not supply a verified antenna height or sector configuration for these selected responses. The project's required **30 m height**, **three sectors at 0°, 120° and 240°**, **43 dBm power**, **6° downtilt** and **100 MHz bandwidth** are explicit demonstration assumptions. `SITE-xx-C1` serving cells are synthetic local IDs. They are assigned to the nearest of the nine selected stations for this example and do not establish actual SKT serving areas. Manufacturer and equipment models remain unverified.

## Street route and example KPI generation

Street geometry was obtained separately from the [OSRM route service](https://project-osrm.org/docs/v5.24.0/api/#route-service) using [OpenStreetMap data](https://www.openstreetmap.org/copyright). The requested route waypoints, in longitude and latitude order, were:

```text
127.0212,37.5112
127.0283,37.4979
127.0489,37.5045
127.0408,37.5164
127.0212,37.5112
```

The request used `overview=full`, `geometries=geojson` and `steps=true`. The resulting street loop follows Gangnam-daero, Teheran-ro, Seolleung-ro, Hakdong-ro and connecting streets. Its OSRM-reported distance is **8,641.7 m**. The sample generator preserved every step-polyline vertex and subdivided segments to at most **15 m** before rounding GPS values to six decimals. The resulting polyline's independently calculated length is **8,640.6 m**.

The CSV contains **676 NR GPS samples**, with example time calculated at **27 km/h**, ending at **1,152.08 seconds**. RSRP, RSRQ, SINR and throughput vary deterministically to exercise the lab's good, fair and poor colors. Events use the `SYNTHETIC_` prefix and each row contains `data_kind=synthetic-example`. No RF solver, field drive test, UE logging or SKT KPI collection produced these values.

The drive CSV's SHA-256 is:

```text

```

## Files and import procedure

All example files are in [examples/gangnam-drive-test](../examples/gangnam-drive-test):

| File | Contents |
| --- | --- |
| `gangnam-nonhyeon-teheran-synthetic-drive.csv` | Importable GPS and synthetic KPI samples |
| `gangnam-skt-registered-sites.csv` | Nine KCA station names, coordinates, permit UIDs and addresses |
| `gangnam-skt-drive-planning-manifest.json` | Importable project containing both the registered site positions and synthetic drive samples |
| `sources.json` | Selected source records, request URLs, collection time, assumptions and CSV checksum |
| `gangnam-street-route.geojson` | Original route geometry and OpenStreetMap attribution |

To display both sites and samples, open **Project artifacts → Import planning manifest**, select `gangnam-skt-drive-planning-manifest.json`, then open **Ray tracing lab** and choose **Fit drive route**. The manifest creates a new project and preserves the existing project.

For CSV-only use, choose **Ray tracing lab → Import drive test CSV**. CSV import updates drive samples; it does not move radio sites. Additional CSV columns such as `road_name`, `operator`, `site_permit_uid` and `data_kind` provide file-level context but are not retained by the lab's current sample parser. The filename and `SYNTHETIC_` events remain visible after import.

The files were checked with the application's `parseDmCsv`, `buildDriveMeasurements`, `upgradeProject`, `sanitizeProject` and `validateProject` paths. All 676 samples and all nine registered positions survived the manifest import transformation. Network, hardware and RF execution readiness remain unverified.

The documented Python collector also passed a replay against the four downloaded public responses. A browser check imported the manifest into a disposable SQLite workspace, preserved the original project, verified all nine saved positions against the source records, rendered good, fair and poor RSRP and SINR colors over the street map, and imported the standalone CSV without moving the sites.
