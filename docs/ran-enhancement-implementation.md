## Saved study contract

`study.schemaVersion = 1` is optional on the existing project schema. Legacy projects keep their working inputs and acquire no invented study. Definitions, baselines and candidate revisions are append-only; selection is a saved comparison reference. A baseline's canonical JSON contains the exact definition version and engineering inputs, excluding transient viewport preferences, results, tasks, management readiness and runtime connection flags. The retained dataset inside the capture remains available even when the working dataset changes.

Supported candidate edits are antenna height (1–300 m), sector transmit power (0–60 dBm), downtilt (0–30°), azimuth (0–359.999°), and bandwidth (5–400 MHz). Site/sector identities must match the captured baseline. Unchanged fields are removed from the change list; duplicate or arbitrary fields and stale revision numbers are rejected. A revert creates a new revision rather than deleting history.

Offline storage limits are explicit: 50 definition versions, 8 baselines, 20 candidates, 50 revisions per candidate, 250 changed fields per revision, 2 MB study history and the existing 3 MB project-artifact boundary. Exceeding a limit blocks the save and retains prior history. This package does not silently prune captures or migrate the existing site/cell limits.

The local path solver uses the explicitly selected working, baseline or candidate geometry/position and an isotropic single transmitter. A height change applies to that selected transmitter. Sector power, tilt, azimuth, bandwidth and changes on other transmitters block candidate execution on both client and API. The result-comparison gate remains blocked until compatible completed outputs and metric semantics exist. The legacy Overview presets are labeled illustrative assumptions to distinguish them from immutable study baselines.

## Measurement source and normalization contract

New GPS imports use `driveMeasurements.schemaVersion = 2`. Elapsed time, LTE/NR technology, serving-cell identifier and WGS84 coordinates remain required. RSRP, RSRQ, SINR and DL/UL throughput are explicit finite numbers or `null`; missing columns and blank / NA / N/A / NULL source values become `null`. Invalid supplied numbers still reject the whole import. Unversioned/version 1 captures keep their strict numeric contract and are neither rewritten nor silently promoted. GPS display height remains 1.5 m above flat ground.

The review maps source columns explicitly and normalizes seconds/milliseconds and Mbps/kbps/bps. Only exact canonical header names receive automatic mapping; vendor names and units require review. Duplicate source headers or reused source columns reject validation. Bounds apply after unit conversion. The limits remain 1 MB UTF-8 source and 2–5,000 samples, with up to 512 source columns. Unknown serving-cell identifiers remain visible and are retained without inventing a network mapping.

`evidence.schemaVersion = 2` retains the exact source CSV (including an original UTF-8 BOM), raw SHA-256 and one versioned mapping recipe. `normalizationSha256` hashes the canonical source-digest/recipe packet and supplies `datasetId`. Changing units or field interpretation therefore changes dataset identity even when raw bytes stay identical. The browser verifies these digests on workspace read/write; the API verifies them and replays the source mapping against normalized samples before committing working datasets or baseline captures. Rejected requests leave the SQLite revision and previous workspace unchanged. Legacy evidence retains its existing contract. Source integrity does not establish field accuracy or physical calibration.

Every KPI reports available and missing sample counts. Average, percentiles and poor-sample percentage use available observations for that KPI. For example, one poor value plus one missing value gives **1 poor / 1 available · 100% · 1 missing**. A selection with no observations shows unavailable statistics and an explicit empty trend; GPS samples remain visible in gray. Trend lines do not connect across missing measurements, and an observed throughput of zero remains distinct from unavailable throughput. Frozen baselines retain their original source and recipe after replacement of the working dataset.

## Retained measurement library contract

`measurementLibrary.schemaVersion = 1` is optional on the existing project schema. Loading or upgrading a legacy project does not create history. **Retain current dataset**, or the next confirmed GPS import, retains a preceding unregistered working dataset with its existing schema and provenance; no absent raw source is invented. The library holds 1–20 append-only records and a nullable `activeId`. Each record stores an ordered version, registration time, full source/sample `inputJson`, its SHA-256 and a content-derived ID. Exact duplicate snapshots reuse their existing record. A changed filename, import metadata or interpretation creates a distinct captured version; normalization identity remains separately visible in source evidence.

The working `driveMeasurements` value must exactly match the selected retained payload, or be null when selection is cleared. Selection is persisted per project. The shared context names the working version, and all working map/analysis views reuse its data. Changing content resets the prior sample ordinal so it cannot silently refer to a different dataset. KPI/RAT and camera preferences remain transient. Baselines capture the selected dataset, rather than the library or future selection; historical propagation contexts retain their independent frozen evidence.

Records cannot be removed, reordered or rewritten through workspace commands, generic controller edits, artifact JSON or API transactions. Browser read/write verifies all snapshot digests and available mapped source evidence; the API also verifies inactive snapshots and the working mirror before committing. Newly retained legacy metadata cannot claim verified measurements, an unknown origin type, invalid dates/digests or an unsupported parser recipe. Its existing source contract is preserved without asserting mapped-source replay. Imports prepared while measurement inputs change reject as stale; unrelated RF edits survive the hash preparation step. Failed database saves retain the visible draft and lock further changes until the existing recovery flow resolves the database.

The library is bounded to 2 MB serialized history and the existing 3 MB project snapshot boundary. A limit rejects the next save rather than pruning evidence. Project artifacts and exported manifests retain the library and selected dataset; each version exports its normalized snapshot and any available original CSV/provenance under `measurement-datasets/vN/`. Serving-cell interpretation is described below. Rich external and neighbor identities, spatial/time alignment, multiple-dataset comparison, remote source collection and larger-scale storage migration remain separate pending capabilities.

## Measurement cell identity contract

Optional `driveMeasurements.cellIdentity` stores exactly `schemaVersion: 1`, `method: manual-review` and a bounded list of bindings. Each binding contains the original `sourceCell`, its LTE/NR `technology` and a nullable internal `targetCellId`. The source identifier remains opaque: PCI, NCI and PLMN are not inferred from it. Bindings must refer to observed source ID / RAT pairs, without duplicates or verification claims. A null target explicitly leaves that identity unresolved, including a source string that happens to equal an internal cell ID.

The working dataset's identity review has search and 50-row pagination. Eligible targets belong to sites whose declared radio technology supports the observation RAT. Save validates target uniqueness and compatibility, rechecks the latest inventory after hashing, then retains and selects the full interpreted dataset as a new library version. An exact duplicate interpretation reuses its existing snapshot. A concurrent dataset change rejects the review; unrelated RF changes are preserved. Failed saves retain the existing visible draft/recovery behavior.

Resolution distinguishes reviewed associations, exact internal-ID matches, unresolved source identities, missing targets, ambiguous targets and radio-technology mismatches. Only uniquely resolved compatible cells expose the associated site action. Working Drive, City and Overview inspectors use the current inventory. Propagation uses the selected working or frozen input inventory/dataset, so later mapping or site edits cannot alter a captured baseline's meaning. Structural validation allows old mappings to survive inventory removal; those targets become visibly unresolved. Original samples, CSV and normalization recipe/digest remain unchanged, while the full dataset snapshot and frozen-input digests include the interpretation. Normalized exports, project manifests, per-version artifacts and Drive analysis reports retain the mapping metadata. These associations remain unverified and do not establish calibrated propagation or live network identities.

## Frozen path request contract

`runCapture.schemaVersion = 1` retains canonical `networkInputJson` and `jobJson` with separate SHA-256 digests, the selected saved reference and definition version, baseline/candidate digests when applicable, and the saved dataset's full canonical content digest/origin. Dataset identity includes the retained raw CSV provenance; it is separate from the raw CSV's source digest. The server checks byte digests and derived saved input values before insertion. Working input changes during preparation reject the request; an old candidate revision remains executable against its unchanged baseline.

The profile records the existing isotropic/concrete assumptions, seed 42, path cap, enabled interactions and 180-second runtime bound. The worker records engine version and execution environment in the stored result. These are reproducibility metadata, not calibration evidence. Completed output contains the bounded capture header; the full inputs remain in the server run record. The request limit is 1.99 MB below the API's 2 MB body limit. Captured execution requires server capability `runContractVersion: 1`; the UI asks for an updated API when that contract is absent. Legacy requests/results are retained without inventing their identity. Imported ray metadata remains unverified.

Cancellation transitions queued/running → cancelling → cancelled. Acknowledgement means the request was accepted; only confirmed worker exit is shown as stopped. Completed output arriving after an accepted cancellation is discarded. The localhost server keeps its single worker slot until exit. A restart records remaining queued/running/cancelling jobs as interrupted, preserving cancellation-request time without asserting an unobserved exit. Lifecycle events record transitions and bounded reasons rather than raw worker stdout. Existing databases gain additive columns and an event table; legacy evidence remains unchanged and no historical events are invented.

Exact retry is available for failed/interrupted/cancelled captured jobs in the active project when the configured runtime is available. The server accepts only the project identifier, validates the retained snapshot/profile and immutable definition history, and copies the original input JSON into a new run with `retryOf`. Receiver, options, input digests and seed remain unchanged; the current working network is not substituted. The original terminal record remains unchanged. Cancellation stays available for an owned running worker even if runtime detection becomes unavailable. Polling failures keep the last confirmed state and evidence visible; scope guards discard late responses after project changes or accepted recovery actions. If record refresh fails after acceptance, the UI retains the receipt, blocks another retry submission and offers a read-only refresh of that accepted run. A worker-launch failure records a failed run and releases the slot.

## Declared cell inventory contract

Optional `cell.inventoryIdentity.schemaVersion = 1` adds explicit LTE/NR technology, paired nullable MCC/MNC, nullable local NCI/ECI, PCI and channel number, carrier label and source reference. Source and verification remain fixed to manual/unverified. Existing project and internal sector IDs are unchanged; registered radio facility positions supply no inferred cell identity. Complete RAT/PLMN/local-ID keys must be unique, while PCI reuse is permitted. Bounds, pinned standards, storage/display conventions and scope are documented in the [inventory identity contract](cell-inventory-identity.md).

The RF identity group requires explicit Save; ordinary RF/position fields retain their previous blur behavior. Unsaved drafts are visible and persist across selected sectors and inspector tabs until the workspace is left. Reset loads the current declaration; Clear removes the optional object. Stale ownership rejects before commit. One save writes identity and activity atomically; failed writes retain the controller draft for recovery. The bounded desktop inspector scrolls while preserving the map's usable height; mobile retains vertical page flow.

Measurement associations still interpret opaque source ID/RAT pairs, without automatic CGI inference or source rewriting. Per-cell RAT now narrows compatible targets and shared inspectors show declared CGI/carrier as unverified. Frozen views use captured declarations; working edits cannot change retained datasets, baseline history or run requests. Source-column identities, neighbor mappings, band/raster validation and carrier execution remain separate pending capabilities.

## Release limits

The complete commercial release is **not achieved** by this package. Real pilot measurement/antenna data, calibration acceptance, multi-site/route RF prediction, connected collector integrations, controlled network changes and representative-user usability acceptance remain unverified or unimplemented. Existing local single-link EM execution is not an end-to-end RAN model. No live SKT connection or production network change is claimed.
