# Frontend migration baseline — Phase 0

This is the characterization checklist for [the refactoring design](frontend-refactoring-design.md), not permission to change product behavior. The original UI at `/` remains the comparison target until a route is verified and switched. The server/API and domain contracts take precedence over illustrative copy if they disagree. In particular, “configured” is not “verified,” coverage/capacity numbers are synthetic, schematic placement is approximate, imported ray paths are unverified, and SQLite is authoritative after hydration.

## Reproducible fixture and observations

- Command: `make check` with Homebrew ARM Node on the local checkout; baseline: 77 Node tests, 19 Python tests, 2 frontend unit tests, 2 proxy/build integration tests, strict TypeScript and production Vite build passed. The numbers supersede the older design draft's 75/17 counts.
- Browser: Chromium, legacy `/`, temporary empty SQLite database, default `RAN Twin · City Pilot` seed, no RT worker configured. Desktop viewport 1280×577: `document.documentElement.scrollWidth=1265`, page height 2626, default heading “5G RAN twin mission control”; screenshot in session scratch `browser_screenshot_1ac2d87177714dd79cb31b1429dc10de.png`.
- Narrow viewport 390×844 on the same fixture: scroll width 837, height 4331; full-page screenshot in session scratch `atlas-legacy-390x844.png`. Existing horizontal overflow is a baseline limitation, **not** a migration acceptance target.
- Fixture requirements for parity testing: empty database seed; two isolated projects (one archived); imported manifest with forged readiness flags; invalid JSON edit; local and imported ray paths; RT unavailable/failed/empty/success responses. Use a disposable SQLite database for browser tests; never mutate a developer's existing `state/` data.

## Route/behavior matrix

Each row must be checked for selected-project switch, persisted reload and invalid/empty input where relevant. The shell must expose exactly one active route, retain breadcrumb/project context and return keyboard focus to main after route navigation. Save failures and 409 conflicts must preserve the local draft with explicit retry/reload, not overwrite a newer revision.

| ID | Default/selected state | Empty, invalid, action and persistence contract |
| --- | --- | --- |
| `overview` | Mission control, active project context, readiness gates and explicitly illustrative KPIs | Select site/scenario; updates remain scoped, synthetic labels survive reload; absent activity remains empty. |
| `projects` | Active and archived project lists | Create, rename, duplicate, switch, archive, restore, delete with confirmation; final-active/archive-only constraints; revision conflict and reload. |
| `artifacts` | Active-project tree with stable paths and file IDs | Empty/absent runs; JSON edit rejects invalid content without mutation, generated files read-only, stale draft protected; download/import/export preserve scope and provenance. |
| `map` | Schematic city and selected site | Select site, estimated placement, 2D/3D and demo/live mode; absent geometry says so; failed city source does not assert calibrated data; Cesium teardown. |
| `stack` | Physical/virtual architecture boundary | Planned topology is not discovered infrastructure; project switch refreshes context. |
| `planner` | Site and cell configuration | Site/cell selection, add/edit numeric validation, project isolation and reload; invalid coordinates rejected. |
| `radio` | Site-specific RU/MMU targets and coordinates | Select site, place/cancel location, validation and reload; schematic source stays `map-estimate`. |
| `ray` | Scene assumptions, ray inputs and job state | Unavailable, queued, running, failed, completed-empty and completed-paths are distinct; invalid inputs reject, imported paths unverified, local paths uncalibrated. |
| `ues` | Planned Grace CPU virtual UE load | Bounds/edits persist per project, never imply deployed UEs. |
| `drive` | DM analysis and route plan tabs | Synthetic no-measurement default, CSV validation, 4G/5G filter, play/pause/reset and exports preserve data provenance. |
| `ab` | Paired package A/B plan | Invalid inputs reject; paired seeds/scene persist; no fabricated execution results. |
| `data` | AI-RAN dataset specification | Invalid specifications reject; zero generated rows remains explicit. |
| `tasks` | Planned task board and project-scoped run records | Add/update validates dependencies; run pagination and selected-run scope; no executed task inferred. |
| `schedule` | Dependency-ordered planned dates | Reject cyclic/invalid scheduling; refresh after project switch/reload. |
| `hardware` | GH200 target topology, rack and inventory tabs | Keyboard tab selection, bounded capacity edits, no discovered link/host claim. |
| `software` | Planned software registry | Versions/channel edits remain unverified, project-scoped and durable. |
| `monitoring` | Threshold configuration, no measurements | No collector/telemetry state stays distinct from zero-value measurement. |
| `activity` | Project-scoped chronological log | Empty log is honest; updates and project switch/reload preserve ordering/scope. |

## End-to-end parity journeys

1. Seed → create/rename/duplicate → switch → edit one project's site → switch back → reload and confirm isolation. Archive/restore/delete only within domain constraints.
2. Save through the development proxy; reject a stale 409, retain unsaved draft, then explicitly reload or retry. Simulate unavailable storage and failed save.
3. Switch site, place/cancel on schematic map, toggle 2D/3D and city mode; enter/leave repeatedly without a second live viewer or stale request.
4. Import/export manifest and edit/reject artifact JSON, preserving immutable IDs/paths and demoting imported/edited provenance.
5. Exercise RT unavailable, queued, failed, completed-empty and completed-with-paths responses with project-generation guards.
6. Navigate accordion groups and every route by keyboard; compare heading focus, selected context, labels, sidebar scrolling and console errors at both viewports.

Do not mark a route migrated from a static screenshot alone. Re-run `make check` and the route-specific browser journey before changing its registry entry.
